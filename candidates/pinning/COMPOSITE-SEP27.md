## Independent register root algorithm retained from our own work

RegisterRoots.cuh, WarpInverse.cuh, CyclicField.cuh, PrefixCyclicField.cuh and RegisterRootCheck.h are byte-identical to our previously submitted checked versions. The underlying GPUMath.h, GLVScalar.cuh, qsb_field_mul and qsb_field_normalize dependencies match those versions. We reuse their established mathematical evidence rather than invent new results or repeatedly run unchanged suites.

Each 128-thread CTA contains four independent 32-leaf trees. A thread owns up to eight original roots, with balanced local products and scratch in the dead weighted-output plane. Four cooperative warp inversions replace the single warp inversion and cross-warp tree publication. The cooperative upper nodes stay distributed as two 32-bit words per lane across inversion. The product and inverse planes use pitches 228 and 116 uint64 words; total shared storage is 11,008 bytes, with six warp synchronization points and no CTA barrier in the new inverse helper.

The 8-lane field product keeps the complete 96-bit cyclic column sum, takes a prefix snapshot and computes the upper portion using complete subtraction borrow. It retains the required carry normalization and full final correction through words zero, one and two under the proved bound. No required carry, prime equivalence, zero isolation or exception handling is removed. The inverse uses the previously ported 832-entry six-divstep scheme with four rows distributed across eight lanes, a 32-batch cap and an independent complete Fermat fallback. Isomorphic scale is applied once. Zero and p-valued roots are isolated as identity while constructing products and restored to zero in the output. Tail indices and the original weighted ABI use the actual root count, not the padded count.

The opportunity is the whole root dependency path and warp utilization, rather than a single removed multiplication. Four independent warp inversions can make progress without cross-warp publication, while retained upper nodes avoid intermediate shared transfers. The cost is four inverse warps instead of one, more aggregate warp work and two words kept live across the inverse. Register pressure, spills, SM scheduler contention and interaction with prepare may outweigh the saved dependency latency. The 16-SM sharing experiment addresses availability of prepare resources but can increase interference with finish. Neither operation counts nor a resource set model demonstrate GPU speed.

## Carrier compatibility, startup checks and fallback

The promoted QsbCarrier.h intentionally skips ordinary-module constant uploads when QSB_NOJIT is enabled and the native carrier is active. A naive inclusion of our ordinary root kernel would therefore read zero scale/weight constants, fail its oracle or compute incorrect roots. We retain the promoted carrier policy for its original kernels and explicitly upload only the new root's ordinary symbols: pin_iso_invu_words and pin_iso_u2ry_words under ISO, or pin_u2ry_words without ISO.

The new module must consequently be loaded and may be JIT-compiled. This integration does not retain the leader's complete carrier-only no-JIT behavior. To reduce exposed startup latency, cudaFuncGetAttributes for qsb_root_register is issued while the existing CPU ladder workers are still building tables; later explicit uploads initialize the module before the root oracle. Host worker synchronization and the promoted table-builder ordering remain intact. This is an overlap attempt, not a measured startup reduction. The new root stays in the normal runtime module and the existing native prepare/finish/table-builder image is unchanged; we did not regenerate a native root carrier locally.

The root entry is enabled only after constants are marked ready and the startup oracle passes. The oracle compares 256 direct cooperative field products to OpenSSL, covering the full eight-by-eight edge Cartesian product and 192 deterministic full-width pairs. It then verifies 29 root shape/pattern cases, including boundaries at 32, 64, 96 and 128, several outer tree/tail boundaries and all-zero/all-p cases. It compares both canonical scaled inverse and weighted residue. These checks are implemented for the official runtime; they were not executed locally.

Host allocation failure or arithmetic mismatch before search disables the new root route and preserves the promoted native QK_RF dispatch, with ordinary baseline dispatch when the carrier is inactive. A CUDA execution error is fatal, because retrying after a poisoned context is unsafe. QSB_REGISTER_ROOTS_OFF skips both the ordinary root load/upload and the root oracle and restores promoted root selection, while leaving the explicitly submitted host topology in place. The runtime prints the selected root path. No correctness check chooses a configuration by timing, seed, hardware assignment or desired score.

It verifies all five reused root headers, arithmetic dependencies, both call sites, carrier fallback, include closure, declaration order, explicit ISO/non-ISO uploads and initialization before the first root startup check. A Python resource-set model checks 120 even device sizes from 18 to 256 SMs. Finish's eight two-SM groups are disjoint, the remainder contains every other SM and the prepare descriptor is their exact union without a duplicated resource. This checks source topology under the API's successful split contract; it is not an execution measurement.

Reused mathematical evidence shipped in register_checks includes 77 root batches / 25,922 roots with tails, zero/p isolation, alternate interleavings and negative wrong-route controls; the literal inline-PTX field interpreter covers 24,080 cases and detects the dropped subtraction borrow mutation; the inverse model covers 43,008 LUT checks, 1,117 inverses, 80,184 row checks and 118 forced fallback cases. Bank-layout evidence is an address model, not a measured memory-wavefront count. These historical evidence files remain clearly identified as prior checks. No claim is made that Python validates native compilation, spills, native instruction selection or GPU races.
