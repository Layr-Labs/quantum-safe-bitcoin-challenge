## Experiment process

1. Build and run the unchanged candidate through Yukon and the documented
   `cmd:python3 harness/gpu_wrap.py --src candidates/pinning/pinning.cu` adapter.
   Use N=24 and the default 1,200-second window for the baseline. Record the
   seed, GPU/toolchain, elapsed time, verified hits, score, and source revision.
2. Make one attributable hypothesis per experiment. Preserve the starting
   source before changes. Use short verified runs to reject poor approaches
   quickly, then longer samples for improvements close to statistical noise.
3. Compare on the same GPU with the same toolchain. Every reported hit must
   independently verify; self-reported M/s alone is not evidence for promotion.
4. Record failures and revert only our own experimental changes. Revisit a
   failed idea only with a concrete change that addresses its measured cost.
5. Publish detailed submission notes after validated improvements, with exact
   commands, results, limitations, attribution, and rejected experiments.

## Hypotheses awaiting baseline

- The hot kernel assembles a 192-byte suffix buffer despite a 75-byte suffix.

  and cross-word patches must remain correct for generated problem instances.
- Fixed-base multiplication reads a 64 MiB point table using 16-bit windows.
  Smaller windows trade additional point additions for improved cache locality.
- One modular inverse per thread remains expensive. Any cross-thread batching
  must justify shuffle, register, divergence, and partial-batch costs against
  the prior failed experiment.

## Frontier audit and literature

The current source was checked byte-for-byte against promoted commit `e5576bd`.
The official progression is 145,499,057 (seed), 197,315,101 (launch bounds and
1M batches), 231,684,949 (projective `u1G` with shared inversion), then
235,880,780 (diagnostic removal). The next 1% bar is about 238,239,588.

Officially rejected variants include 128-thread/four-block launch geometry,
two forms of warp batch inversion, and shuffle inversion plus an 8M batch.
The 8M batch has not been isolated on the current lean kernel. Public proxy
scores moved differently from official scores, so short-run verified scores
are filters rather than promotion evidence.

Submission `1e4b4c7` reports an earlier first-block SHA hoist at about 237.1M/s.
All emitted hits verified, but hit-implied work was materially below its
candidate counter; exact counts were not published. Our decisive checks must
therefore include full verification and candidate-count consistency, not only
valid sample hits or self-reported rate.

The [NVIDIA Ada tuning guide](https://docs.nvidia.com/cuda/ada-tuning-guide/)
documents a 64K-register file per SM, 48 maximum warps per SM, and the large
AD102 L2 cache. The [CUDA best-practices guide](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/)
warns that higher occupancy does not automatically improve performance and
recommends measuring launch bounds, registers, and spills together. This agrees
with the official regression from forcing four blocks per SM.

The [gECC paper](https://arxiv.org/abs/2501.03245) identifies modular inversion,
integer multiply-add count, and big-integer memory layout as GPU ECC bottlenecks.
Its batching result is relevant background, but public attempts show that a
correct mathematical reduction can still lose here through shuffles, live
state, and spills. Any revisit is gated on profiler evidence.

A stronger untouched algebraic hypothesis is to form `P+C` and `P-C` together
from projective `P=u1G`. Both additions share their `V=xC*Z-X` terms and end
with the same projective Z. Relative to the current sequential `P+C`, then
`(P+C)-2C`, this can save nine field multiplies and one square per candidate,
including cheaper common-Z normalization. A separate 5,000-vector CPU property
test reproduced both affine results. This remains a later prototype; the SHA
experiment stays isolated first.

## Shared-denominator recovery experiment

The next isolated change ports `qsb_affine_finish_prepare/finish` from the
promoted sibling Subset candidate. Both tracks use byte-identical field and SHA
headers and the same homogeneous convention, `x=X/Z` and `y=Y/Z`. For affine
`R=(xR,yR)`, the helper constructs `D=xR*Z-X=Z*(xR-xP)` and
`W=Z*D=Z^2*(xR-xP)`. One inverse of W therefore yields both `1/Z` and the
affine addition denominator needed to recover `P+R` and `P-R`.

This replaces two mixed projective additions plus two-point normalization
(`25M + 4S + I`) with a shared affine finish (`10M + 3S + I`), saving 15 field
multiplies and one square per candidate. The first prototype copies the promoted
helper exactly and leaves the kernel ABI and debug path unchanged. This avoids
combining arithmetic changes with later removal of unused `neg_2u2R` inputs.

The helper has the same incomplete exceptional cases as the prior path when
`P=+/-R`, and the fixed-base routine already has an undefined zero-scalar case;
both have negligible probability for the SHA-derived input stream. Validation
requires exact control-hit containment across both recovery IDs, all-hit CPU
verification, a native resource report, and a short paired rate win.

The diagnostic native `sm_89` build used 128 registers and a 320-byte stack
frame for the production fast path, with no spill loads or stores. The generic
fallback remained separate at 544 bytes of stack and 24 bytes of spill traffic,
and the debug kernel was unchanged. An eight-second launch warmed the new fat
binary before measurement.

A 15-second same-seed semantic check used seed `1592962926`. The unchanged
frozen SHA-tail control produced 441/441 verified hits at 256.8 M/s. The
shared-denominator candidate produced 470/470 verified hits at 278.8 M/s. All
441 control tuples appeared in the candidate output, with 29 additional valid
tuples from its longer traversal. Recovery IDs remained balanced at 236/234.

## Block-wide inverse experiment

The next isolated change replaces the per-thread inverse of the shared affine
denominator with one product-tree inverse per 256-thread block. A prior
warp-only Pinning attempt still issued one inversion stream per warp; the
two-level block tree reduces eight warp inversion streams to one, at the cost
of field products, shuffles, two barriers, and 2,560 bytes of shared memory.

The first test uses the latest carry-preserving `qsb_field_mul` plus exact
`qsb_warp_inverse` and `qsb_block_inverse` control flow from the sibling
candidate. Tail blocks keep all threads alive through the collectives and use
one as the inactive lanes' factor. Entirely empty blocks return uniformly.
Correctness requires every active lane to receive its own inverse, exact
same-seed hit containment, full CPU verification, and no barrier divergence.
The inherited zero-denominator exceptional cases are vanishingly rare in the
benchmark stream and are recorded separately from this performance test.

The native `sm_89` fast path compiled at 128 registers, a 368-byte stack,
2,560 bytes of shared memory, 108-byte spill stores, and 52-byte spill loads.
The prior field checkpoint used a 352-byte stack and 24-byte spill loads/stores.
The collective therefore increases spill traffic, but remained comfortably
within the same two-block occupancy target.

After an eight-second warmup, a 15-second same-seed semantic check used seed

spill stores/loads before the mask. It retained 128 registers and 2,560 bytes
of shared memory. This unexpected improvement comes from returning unusable
lanes immediately after the collective, shortening later live ranges.

the short-run resolution and materially strengthens the collective failure

## Direct SHA-state consumption

The next small experiment removes two byte round-trips from the ranked fast
path. SHA-256 state words are already the big-endian digest words: the scalar
limbs can be assembled directly from `s2`, and the N-bit gate can test the high
bits of `hs[0..]` without materializing a 32-byte digest. In single-hash mode,
the second-hash padded block is also skipped before its byte buffer is built.

The generic and easy diagnostic paths retain byte construction where their
interfaces require it. The direct scalar limb order and word gate are copied
from the sibling implementation and independently checked against the prior
byte loops. The performance gate is the same 15-second containment check and a
30-second fresh-seed pair only if the resource report and first rate are sound.

A CPU audit compared 100,000 random SHA states against the old scalar byte
loop and checked the word gate for every N from 1 through 256; all cases
matched. The existing tail audit also retained all 2,320 SHA256d comparisons.
The native fast-path resource report was unchanged at 128 registers, a
352-byte stack, 28-byte spill loads/stores, and 2,560 bytes of shared memory.

After an eight-second warmup, a 15-second same-seed comparison used seed
`1364578372`. The zero-safe control ran at 417.6 M/s with 769/769 verified
hits and score 426,488,491. The direct-state candidate ran at 417.9 M/s with
770/770 hits and score 426,491,833. All 769 control tuples appeared in the
candidate result. The peak-rate ratio was only 1.00072, below useful standalone
resolution, so no 30-second pair was spent on it. The change is retained as a
verified neutral cleanup and because direct scalar words simplify the later
folded-base experiment; it is not claimed as a performance improvement.

## Signed-table XYZZ fixed-base experiment

The next major experiment ports the accepted `6d97bb4` fixed-base path while
retaining the current SHA frontend, scalar multiplication, zero-safe block
inverse, shared affine recovery, and accepted field header. It recodes the
already reduced `u1` into 16 nonzero signed odd digits, halves the affine table
from 64 MiB to 32 MiB, and accumulates table points in XYZZ coordinates before
one conversion to the homogeneous interface.

The table remains problem-independent G/2 in this stage. Host-generated 512 KiB
ladders feed a parallel GPU table builder, whose output is spot-checked against
OpenSSL before search. Folding `neg_r_inv` into the table is deliberately a
later experiment so signed geometry and removal of per-candidate scalar
multiplication remain separately measurable.

The accepted incomplete XYZZ addition has four exceptional effective scalar
residues. The production zero-denominator mask prevents any resulting infinity
from poisoning the block, but initially suppresses the singular lane. A strict
exception repair and targeted coordinate audit are tracked separately; random
encounter probability over a benchmark run is effectively zero. Ordinary
validation still requires exact same-seed hit containment and full CPU
verification before performance evidence is considered.

The completed signed-table source has SHA-256
`d2bbf43d9d47ebda4e6a3e35b0b6d3e1e1fa24b0c84693fcbdc77dd2130bcf59`.
Its native Ada fast kernel retained 128 registers and 2,560 bytes of shared
memory. The stack grew from 352 to 384 bytes; spill loads/stores grew from
28/28 to 36/40 bytes. The builder itself uses 128 registers, a 120-byte stack,
and no spills.

The first cold eight-second run used seed `741231449`. It built the host
ladders and GPU table inside the external timeout, then completed one full
sequence and part of the next. Its 177 verified tuples were an exact subset of
the direct-state control, including an exact 142-of-142 match for the fully
completed first sequence. The harness nevertheless extrapolated the post-start
535.3 M/s rate across cold table construction, overreported candidates, and
printed a Poisson warning. This is a short-timeout accounting artifact rather

## Accepted level-packed shared inverse tree

The block-wide denominator inversion previously built a redundant all-reduce
inside each warp and then repeated the pattern over the eight warp products.
Counting the stride-one copies correctly, that implementation executed 2,752
field multiplications and 86 warp-level multiplication sequences per 256-lane
block. The replacement builds one level-packed binary product tree in shared
memory, inverts its root once, and propagates inverses back to all leaves using
`(L*R)^-1*R=L^-1` and `(L*R)^-1*L=R^-1`.

Each tree level stores its left half before its right half in limb-major order.
This gives contiguous operands across active lanes and makes a sibling a simple
half-level XOR. The immutable product tree occupies 16 KiB and the internal
inverse levels occupy 8 KiB. The resulting collective uses 765 field
multiplications, 31 warp-level multiplication sequences, 16 CTA barriers, and
one inversion. Inactive tail lanes and the fixed singular cases still enter as
multiplicative identities, so every thread reaches every barrier.

`audit_shared_tree.py` checked 211 full 256-value blocks modulo the secp256k1
prime, including all-identity tails, active counts around warp and half-block
boundaries, zero replacement, field edges, and random mixtures. Every returned
leaf multiplied by its effective input to one. A three-second GPU smoke then
verified 170/170 emitted hits and passed the benchmark variance check.

Native Ada compilation retained 128 registers and the 304-byte fast-kernel
stack. Fast-path per-thread spills improved from 40-byte stores / 36-byte loads
to 24/24, while shared memory rose from 2,560 to 24,576 bytes. Two 256-thread
blocks still fit: registers remain the limiting resource. The root inversion,
executed by only one lane per block, reports 28-byte stores / 32-byte loads in
its helper; its amortized cost is negligible relative to the eliminated field
multiplications.

## Short-run policy after the constant-point checkpoint

The accepted kernel is now fast enough that long exploratory runs have poor
information value.  New experiments use a staged gate:

1. Prove the changed algebra, address map, and output tags independently on the
   CPU, including boundary values and inactive collective lanes.
2. Compile for native `sm_89` and reject resource regressions before timing.
   The current checkpoint is 128 registers, a 288-byte fast-kernel stack, zero
   fast-caller spills, and 24,576 bytes of shared memory.
3. Warm the JIT, then use a same-seed 2--4 second screen.  Each arm must verify
   at least 100 hits, cover both recovery IDs, emit no duplicates, and contain
   exactly the control tuples over the common completed frontier.
4. Run the reverse order only when the first ratio reaches 1.005.  Retain a
   change only when both orders and their geometric mean clear that threshold.

This policy concentrates GPU time on decisions.  Correct-but-neutral changes
are recorded and reverted instead of being accumulated into the production
source.

## Literature-guided 15-term table design

The regular odd recoding in this candidate is the Joye--Tunstall recurrence:
choose an odd representative, take
`e = (M mod 2^(w+1)) - 2^w`, and advance by
`M = (M-e)/2^w = 2*floor(M/2^(w+1))+1`.  This is the regular signed-digit
construction described in *Fast and Regular Algorithms for Scalar
Multiplication* ([ePrint 2011/338](https://eprint.iacr.org/2011/338.pdf)) and
subsequent regular-recoding work
([ePrint 2015/036](https://eprint.iacr.org/2015/036.pdf)).

The current sixteen width-16 terms require `16 * 2^15 = 524,288` affine
points, or 32 MiB for x and y.  Removing one mixed addition requires fifteen
digit widths whose sum covers 256 scalar bits.  Convexity of the per-window
cost `2^(w-1)` makes the balanced integer split minimal: fourteen width-17
terms and one width-18 top term.  That design has
`14 * 2^16 + 2^17 = 1,048,576` points, exactly 64 MiB of coordinates.  It saves
one 8M+2S XYZZ mixed addition and four 128-bit coordinate loads per candidate,
at the cost of doubling the random table footprint.  A complete local address
and recoding audit is the mandatory first gate; native resource and short A/B
results decide whether the 4090's L2 can retain enough of the larger table.

## Table-load cache-policy probe

The remaining fixed-base loop performs sixteen random point reads: 64
128-bit global loads, or 1,024 logical bytes per candidate.  NVIDIA documents
L1 as per-SM and L2 as device-wide, and documents `__ldcg` as a load using the
corresponding cache operator for CUDA vector types
([CUDA C++ Programming Guide](https://docs.nvidia.com/cuda/cuda-programming-guide/),
[CUDA 12.5 load-function reference](https://docs.nvidia.com/cuda/archive/12.5.0/cuda-c-programming-guide/index.html)).
Because this access stream is random over a shared 32 MiB table, bypassing L1
may avoid overfetch and eviction of shorter-lived data while preserving L2
reuse across SMs.  The isolated probe changes only the four `ulonglong2` point
loads to `__ldcg`; its address audit passes.  The compile gate requires the
accepted register, stack, spill, and shared-memory allocation, plus confirmation
of the intended global cache operator in SASS.  Its expected gain is small, so
one forward 3-second run is enough to reject it below 1.005.

A direct Nsight Compute sample of the accepted binary was also attempted with
a 45-second cap.  The host denied access to NVIDIA performance counters with
`ERR_NVGPUCTRPERM`; no counter values were collected.  Rather than spend more
time on unavailable telemetry, the experiment queue uses static SASS/resource
inspection followed by short controlled A/B runs.

This resolves the central tradeoff: on the target RTX 4090, removing one mixed
XYZZ addition and four 128-bit coordinate loads does not repay doubling the
random table footprint from 32 MiB to 64 MiB.  Further work returns to the
promoted 16-term geometry.  The nonuniform recoder and its exhaustive audit are
retained here as a reproducible negative result, not as the production base.

## Native-code triage for the next short runs

CUDA 12.6 `sm_89` builds and `cuobjdump`/`nvdisasm` inspection provide a cheap

- The compact 16-bit digit representation saves 32 stack bytes but adds 120

## L2 persistence probe

An isolated host-side probe places the contiguous X/Y table in one CUDA access
policy window and requests the device's effective persisting-L2 set-aside.  On
the development RTX 4090, the queried L2 size is 72 MiB, the maximum persisting
set-aside is 49.5 MiB, and the maximum access-policy window is approximately
128 MiB.  The resulting hit ratio is 1.0 for the accepted 32 MiB table and
0.7734375 for the 64 MiB 15-term table.  CUDA treats this policy as a hint, so
those numbers establish only that the experiment is valid; a short A/B run
must decide whether it helps.

The reviewed probe uses the effective limit returned by `cudaDeviceGetLimit`,
keeps uploads, counter resets, kernels, and readbacks on the same explicit
stream, and synchronizes setup before benchmark timing.  Both the 32 MiB and
64 MiB forms compile with production kernel resources unchanged, and all
table, recoding, shared-tree, and SHA-tail audits pass.

A separate generic RTX 4090 microbenchmark then tested the hardware question
without using candidate source.  Its one kernel issued four independent random
128-bit loads per loop step over either a 32 MiB or 64 MiB array.  Baseline and
persisting streams used identical indices and checksums in three alternating,
reverse-order pairs of two-second arms.  The runtime accepted the full 49.5 MiB
set-aside, a 1.0 hit ratio for 32 MiB, and a 0.7734375 ratio for 64 MiB.

| random-load array | baseline median | persisting median | paired ratio |
| --- | ---: | ---: | ---: |
| 32 MiB | 1,184.79 GiB/s | 1,184.53 GiB/s | 0.999781 |

## Lazy inverse-tree canonicalization

The packed inverse tree performs 765 field products per 256-thread block: 255
to build the tree, 254 to propagate internal inverses, and 256 to return the
leaves.  Its carry-preserving field multiplier already returns an exact residue
in `[0, 2^256)`; the final comparison and subtraction merely select the
canonical representative.  Internal tree nodes can therefore retain a
noncanonical but congruent value.  Normalizing only the root before `_ModInv`
and each returned leaf reduces canonicalizations from 765 to 257 per block,
eliminating 1.984375 small predicate/subtraction sequences per candidate.

The actual 241-instruction PTX multiply was interpreted over 4,928 boundary
and random pairs, including `(p-1)^2`, whose raw result deliberately appears as
`p+1`.  Twenty-four full tree blocks returned all 6,144 expected canonical
inverses.  An independent adversarial review added 12,000 pairs with both
operands in `[p, 2^256)`, 8,200 normalization-boundary representatives, and
five complete tree patterns that propagated 2,072 noncanonical internal
values; lazy and eager leaves matched bit for bit.

On the promoted 16-term geometry the isolated patch keeps 128 registers, a
288-byte stack, zero caller spills, and 24,576 bytes of shared memory while
removing 24 encoded fast-kernel slots and 22 non-NOP instructions.  Combined
with the XYZZ schedule, it keeps the latter's 272-byte stack and spill removal
and removes another 16 slots.  The dynamic saving is real but likely below the

short GPU evidence or the isolated XYZZ ranked result.

The isolated XYZZ schedule supplied that ranked calibration.  It scored
**557,730,322**, only 25,823 or **0.0046%** above the promoted source, and was
rejected.  Its 32-slot reduction, 16-byte stack reduction, and removal of the

effect.  It remains algebraically safe and can relieve pressure in a bundle,
but static stack and code-size improvements no longer count as positive
performance evidence by themselves.  New bundles must remove work executed on

## Fifteen-term radix-373 GLV design

The next algorithmic target uses the secp256k1 endomorphism rather than a wider
one-dimensional table.  The GLV decomposition writes
`k = k1 + lambda*k2 (mod n)`, where applying `lambda` to an affine point keeps
`y` and multiplies `x` by the field cube root `beta`.  Bitcoin Core's
`libsecp256k1/src/scalar_impl.h` documents the exact lattice basis, rounded
`g1`/`g2` division constants, and 128-bit component proof used here; the
underlying method is Gallant, Lambert, and Vanstone, *Faster Point
Multiplication on Elliptic Curves with Efficient Endomorphisms* (CRYPTO 2001).

A rational Eisenstein radix of 373 has `373^2 = 139129` two-dimensional
residue classes.  The 139,128 nonzero classes form exactly 23,188 free orbits
under the six units `+/-{1,lambda,lambda^2}`.  Fifteen chunks with one 96-byte
record per orbit occupy:

```text
15 * 23188 * 96 = 33,390,720 bytes = 31.843872070 MiB
```

Each record can hold one common `y` and two x orientations.  The third follows
from `beta^2*x = -x-beta*x (mod p)`, so approximately one third of digits need
one four-limb field addition/negation instead of another 32-byte load.  Sign is
free through `y -> p-y`.  This preserves the successful roughly 32 MiB table
footprint while reducing fixed-base accumulation from sixteen points to
fifteen: one 64-byte point lookup and one `8M+2S` mixed XYZZ addition disappear
per candidate.  A small 32-bit map from residue pair to orbit/orientation/sign
is approximately 544 KiB and should remain hot in L2.

The difficult coverage condition now has an exact proof and executable audit.
Choose the unit-invariant nearest representative for each residue class.  Its
Eisenstein norm is at most 46,129 and each of the three Voronoi support forms
`2a-b`, `2b-a`, and `a+b` has absolute value at most 373.  The device starts
from the published rounded split and selects the first of the raw point and
its six shortest lattice neighbours whose support forms fit the exact bound
`T = 373^15 - S - 1`.  Trying the four basis neighbours first covers the hot
cases; the final `+/-(v2-v1)` pair completes the nearest-cell argument on a
cold branch.

After fourteen radix divisions, a support form of the remaining quotient is
bounded by

```text
(T + 373*(373^14-1)/372) / 373^14 < 373.
```

It is integral, hence at most 372.  This lies strictly inside the final
radix-373 Voronoi cell, so the fifteenth digit equals the remaining quotient
and the next quotient is exactly zero.  Thus every scalar has exactly fifteen
digits; this is a coverage proof rather than a random-search inference.

`audit_glv_radix373.py` exhaustively constructs all 139,129 residue mappings,
checks all 23,188 unit orbits and the proof inequalities, and verifies scalar
congruence, exact reconstruction, table orientation, and termination.  The
current deterministic run added 100,000 random scalars plus boundary cases;
all terminated, and the observed fourteenth-quotient support maximum was 372
against the proven 372 limit.  An earlier 200,000-scalar nearest-cell run also
had zero failures.  Zero digits occur with
roughly `1/139129` probability per chunk and need a rare divergent slow path;
the common path remains a fixed fifteen-point accumulation.

The rounded split and complete radix recoder have now been implemented and
checked against independently generated exact vectors.  A self-contained
RTX 4090 microbenchmark measured about 13.67 billion raw splits/s and about
4.0 billion complete split/adjust/recode operations/s.  A separate public-data
table geometry probe measured the 96-byte GLV layout at 1.0810 times the
synthetic lookup rate of the current 64-byte, 32 MiB layout; storing all three
x orientations in 128-byte records was slightly slower than the control.

## Radix-384 pipelined follow-up

While the radix-373 archive waited for validation, a parameter sweep exposed a
useful discontinuity. The exact 15-digit support threshold first contains the
nearest GLV cell at radix 373, but the entire independent-rounding
parallelogram first fits at radix 383. Radix 384 is one step larger and factors
as `3*128`, making quotient/remainder extraction cheaper. For a raw split
`z = f1*v1 + f2*v2` with `|f1|,|f2| <= 1/2`, the maximum of each linear support
form occurs at a parallelogram corner. The three exact maxima are all below
`384^15 - 384*(384^14-1)/383 - 1`, with the tightest using 95.06% of the bound.
Thus no per-scalar support check or lattice adjustment remains.

Because 384 is even and divisible by three, two nonzero unit orbits have sizes
two and three instead of six. Exhaustive enumeration gives 24,575 ordinary
six-element orbits plus one of each exceptional size, or 24,577 stored records
per chunk. The 96-byte table becomes 35,390,880 bytes = 33.751373291 MiB.
`audit_glv_radix384.py` checks every one of the 147,456 residue pairs, both
exceptional orbits, the raw-split bound, exact scalar reconstruction, and
termination. Its 100,012-scalar run had no tail failures.

A four-round public RTX 4090 lookup A/B found the larger table essentially tied
with radix 373: 2,516.60 versus 2,518.02 million synthetic candidates/s, both
about 1.081 times the current one-dimensional layout. The complete public
split/recode probe improved from roughly 4.0 billion/s at radix 373 to
4.189 billion/s at radix 384. Replacing division by 384 with an explicit
shift-by-seven followed by exact reciprocal division by three raised that to
4.211 billion/s. The follow-up therefore keeps the same fifteen curve terms
and submits the simpler raw-split path as an independently scored delta.

## Hybrid block/warp batch inversion experiment

The promoted v19 normalization path batch-inverts 256 projective `z` values
with a full binary tree in shared memory. Eight upward levels and seven
downward levels require repeated whole-block synchronization. The current
experiment retains the first three block-wide reductions, leaving 32 products
that each cover eight lanes. Warp zero then uses the existing shuffle-based
batch-inversion primitive to invert those 32 subtree products with one scalar
`_ModInv`. Two block-wide downward levels expand the subtree inverses before
the unchanged leaf reconstruction.

This changes only `qsb_block_inverse` relative to the exact promoted v19
runtime source. It removes ten block barriers and the top shared-memory tree
passes. The packed limb-major arrays shrink from `products[4][512]` and
`inverses[4][256]` to `products[4][480]` and `inverses[4][224]`, reducing
static shared memory from 24,576 to 22,528 bytes. The final 64-to-32 product
level is consumed by the same lanes that write it, so its CTA fence is omitted;
the complete path executes six CTA barriers instead of sixteen. An exact CUDA 12.6 `sm_89`
build reports 128 registers, a 224-byte fast-kernel stack, and no fast-kernel
spill loads or stores. Fast-kernel text grows from 167,424 to 176,512 bytes
because the shuffle exchange is instruction-heavy, so the ranked outcome will
measure the barrier-latency saving against that additional instruction issue.

`audit_hybrid_inverse.py` models the source offsets and active-lane identity
mapping directly. It checks zero, one, full-width, irregular tail, and random
active masks against independent modular inverses; 211 deterministic cases
pass. The experiment is intentionally isolated from the queued GLV changes so
its ranked result can identify the inverse-tree effect.

## Final-carry field-reduction audit

An independently inspected submission identified a correctness edge in the
sparse double-fold field reduction. After the second fold, the current v19
multiply and square store the low 256 bits and drop a possible carry. For the
valid field input `a = p - 65537`, the square path produces a carry of one:
the dropped result is `0x1fc30`, while the exact residue is `0x100020001`.
Folding the carry by `2^256 == 2^32 + 977 (mod p)` recovers the exact value.

The correction is algebraically valid for every 256-bit input. After the first
fold the high part is bounded by `2^32+977`; after the second fold the whole
value is below `2^256 + 2^66`, so its final carry is at most one and the low
remainder is small whenever that carry occurs. Adding `2^32+977` cannot
overflow again in that case. This path is rare for uniformly distributed field
values, while the extra instructions sit in every hot multiply and square. It
is therefore retained as a separate correctness/performance experiment rather
than being bundled into the hybrid inversion submission.

## External root inversion with internal-node checkpoints

The next experiment returns to the exact promoted `5724411` runtime and moves
the single product-tree root inversion out of the 256-thread search kernel.
Submission `4745a544` by `odinfree` supplied the material unpromoted insight:
isolating roots in a dense kernel avoids keeping 255 idle threads resident
while lane zero executes `_ModInv`. The implementation here independently
adapts that idea to the promoted interleaved-table and lazy-normalization base,
then removes the duplicated work that limited the sibling experiment.

The prepare kernel computes the same 256 leaves and upward product tree as
v19. It publishes one root per CTA and checkpoints internal nodes 256 through
509. Four fields cross the kernel boundary: `C=ZZ*d^2`, `Y`, `W=ZZ^2*d`, and
`ZZZ`. This is the same 128-byte state footprint as retaining `d,Y,ZZ,ZZZ`, but
it preserves each leaf `W` and moves the `C` square and multiply from finish to
prepare. The middle kernel launches 128 threads per block over the compact root
array; every active thread normalizes one root and runs `_ModInv`. The finish
kernel restores its saved `W` leaves and 254 internal nodes, expands the root
inverse downward, normalizes the 256 returned leaves, and evaluates the same
two direct-XYZZ recovery formulas.

For `N` candidates and `B=ceil(N/256)` CTAs, the cross-kernel logical traffic
is `256N + 16384B` bytes: 128-byte state write and read per candidate, 8,128-byte
internal-node write and read per CTA, and 128 bytes of total root traffic per
CTA. A full CTA therefore transfers 320 bytes/candidate; a 16M batch transfers
exactly 5 GiB. The padded allocations are 2,048 MiB for state, 512 MiB for tree
nodes, and 2 MiB for roots. At the v19 frontier rate, 320 bytes/candidate is
about 181 GB/s of logical traffic, leaving substantial headroom against RTX
4090 DRAM bandwidth while keeping every large access lane-coalesced.

The arithmetic is unchanged. Recovery performs `2L + 8U + 765B` field
multiplies, `L + 3U` squares, and `B` inversions, where `L=256B` lanes and `U`
is the number of usable candidates. A full usable CTA including fixed-base
work executes `33,021M + 8,704S + 1I`. The split executes eight CTA barriers in
prepare and eight in finish, equal to v19's sixteen; the default stream's two
kernel boundaries provide the cross-kernel ordering. Normalization remains
exactly one root immediately before inversion and one result per returned
leaf.

CUDA 12.6.85 for `sm_89` reports 128 registers, 64 bytes of stack, 16 KiB of
shared memory, and zero spills for the fast prepare kernel; 94 registers,
64 bytes of stack, 24 KiB shared, and zero spills for finish; and 96 registers,
120 bytes of stack, no shared memory, and zero spills for the root kernel. The
promoted combined fast kernel used 128 registers, a 224-byte stack, and 24 KiB
shared. Static fast-path text grows from 10,464 slots to 12,152 across all three
kernels, but each independently scheduled candidate kernel is smaller than the
monolith.

`audit_external_pipeline.py` independently reconstructs the checkpointed tree
and compares the `C/W` cut against the original recovery algebra. It passed 210
zero, tail, full, and random active-lane trees plus 10,000 recovery cases. It
also source-checks the exact node bounds, normalization order, state transform,
launch stages, and allocation stride. The production signed-window audit was
repaired to match the promoted 16-by-16-bit geometry and now passes 3,564
boundary scalars, 50,000 random scalars, every one of 524,288 table offsets,
and every builder decomposition. The original shared-tree and SHA-tail audits
pass 211 and 2,320 cases respectively.

## Hierarchical root batching and vector checkpoint I/O

The external-pipeline follow-up removes the remaining scalar-inversion fanout.
A full 16,777,216-candidate launch produces 65,536 search-CTA roots. The prior
pipeline normalized and inverted every root independently. This version groups
those roots into 256 checkpointed product trees, builds one final 256-leaf tree
over the group roots, executes `_ModInv` once, and expands the inverse through
both tree levels. Thus the full batch uses one scalar inversion rather than
65,536. Partial search batches use the same fixed-width collectives: inactive
candidate lanes, unused roots in the last group, and unused group roots in the
top tree all contribute the field identity.

The new root path has three compact kernels. `qsb_root_group_prepare` reads up
to 256 main roots per CTA, computes 255 tree products, checkpoints nodes 256
through 509, and publishes the group root. `qsb_invert_super_roots` launches
exactly one 256-thread CTA and reuses the original shared-memory block inverse
over the at most 256 group roots. Its lane-zero root is normalized immediately
before the sole `_ModInv`. `qsb_root_group_finish` restores each group's
immutable nodes, accepts the canonical group-root inverse, and expands it to
canonical inverses for the original search CTAs. Default-stream launch order is
prepare, group prepare, super inverse, group finish, and candidate finish.

For a full batch, the extra level performs 196,605 field multiplications: 765
per root group plus the 765 multiplications in the final block inverse. This is
about 0.01172 multiplication per searched candidate. The hierarchy retains
the old read/write of every main root and adds about 6 MiB of checkpoint and
super-root traffic, exactly 0.375 byte per candidate. Its added allocations are
2 MiB for padded group-tree checkpoints and 8 KiB for the group roots. Together
with the 2,048 MiB candidate state, 512 MiB first-level checkpoint, and 2 MiB
main-root buffers, the pipeline allocates about 2,564 MiB.

The checkpoint state also changes from sixteen scalar 64-bit SoA planes to
eight `ulonglong2` planes. Adjacent limbs of each of `C`, `Y`, `W`, and `ZZZ`
share one naturally aligned vector. The logical layout remains bijective and
the allocation remains exactly 128 bytes per candidate, or 2 GiB for the full
batch. CUDA allocation alignment and the 16-byte plane stride make every
element aligned. Actual `sm_89` SASS now contains eight `STG.E.128` state
stores in prepare and eight `LDG.E.128` state loads in finish, replacing
sixteen scalar operations in each direction. Tree and root traffic remains
scalar and separate.

The combined CUDA 12.6.85 build has zero spills in every ranked kernel. Fast
prepare uses 127 registers, 64 bytes of stack, 16 KiB shared, and 6,208 SASS
slots. Fast finish uses 94 registers, 64 bytes of stack, 24 KiB shared, and
4,488 slots. Slow prepare uses 128 registers, 256 bytes of stack, 16 KiB
shared, and 6,536 slots; slow finish has the same 94-register/4,488-slot shape
as fast finish. The group prepare and finish kernels use 44 registers, zero
stack, 16/24 KiB shared, and 232/400 slots. The single super-root inverse uses
114 registers, 120 bytes of stack, 24 KiB shared, and 1,768 slots. Relative to
the scalar-I/O external pipeline, vectorization removes 144 slots from the fast
prepare/finish pair and lowers fast-prepare allocation by one register.

`audit_superbatch_roots.py` independently models both tree levels and checks
137,492 roots over twelve boundary sizes from one through 65,536. Every returned
value multiplied by its input equals one modulo the field prime. The source
checks require the exact five-kernel order, group-count ceilings, and reuse of
the checkpoint helpers. `audit_vector_state_layout.py` proves the old and new
byte layouts contain exactly the same logical cells, checks all 16-byte and
warp-contiguity invariants, and verifies the production allocation is exactly
2 GiB. The external-pipeline audit still passes 210 split trees and 10,000
recovery comparisons; the original product-tree, final-carry, signed-window,
and SHA-tail audits also pass. Performance remains intentionally unclaimed
until ranked hardware measures the extra tree arithmetic and launches against

## Compile-time removal of the unreachable second-hash path

The ranked host selects `FAST_TAIL=true` only when `single_hash && !easy` and
the input has the exact 75-byte/31/67/9995 pinning layout. Inside the templated
finish kernel, however, the original `if (single_hash) continue` depends on a
runtime argument. PTXAS therefore retained the complete second public-key hash
in the fast specialization even though the host can never request it.

Changing that guard to `if (FAST_TAIL || single_hash) continue` exposes the
existing host contract at compile time. It does not alter any reachable case:
`FAST_TAIL=true` already implies `single_hash=true`, while for
`FAST_TAIL=false` the expression reduces to the original runtime condition.
The easy and double-hash modes continue to use the fallback specialization.

CUDA 12.6.85 `sm_89` reduces fast finish from 4,488 to 3,136 SASS slots, a
1,352-slot or 30.12% reduction. Registers fall from 94 to 92; the 64-byte
stack, 24 KiB shared-memory allocation, and zero-spill result are unchanged.
Fast prepare and every fallback or auxiliary kernel are instruction-identical
to the hierarchical control. `audit_fast_tail_contract.py` binds the source
predicate, template launches, guard position, and second-hash code, then checks
that the second hash executes exactly when `single_hash` is false across the
host selection matrix.

A separate inline H0-only compressor was screened after this correction. Once
the unreachable second hash was removed, returning only digest word H0 saved
just eight more slots and did not reduce the 92-register allocation. A public
no-inline H0 submission had also regressed relative to its full-SHA sibling.
The H0 change is therefore omitted so the ranked delta remains the larger,
safer compile-time path elimination.

## Mixed table addressing and a fully deferred affine anchor

The mixed 15-chunk schedule doubles the table to 64 MiB but removes one XYZZ
addition. Its first chunk has an 18-bit signed odd digit and the other fourteen
have 17-bit digits. The rolled production loop now carries the flat base of
chunk 2 and advances it by 65,536 entries per iteration. This is algebraically
the same as `gt_offset(c)`, but CUDA 12.6 emits the recurrence as uniform
address arithmetic. On `sm_89` it removes the seed candidate's one-time local
spill, lowers both prepare kernels from 128 to 127 registers, and removes 24
SASS slots. `audit_stream_recode.py` exhausts the 1,048,576-entry map as well
as 51,404 scalar recodings and binds the flat recurrence to the source.

The ordinate is then kept in affine-anchor-deferred form through the complete
rolled addition chain. If an XYZZ point represents actual ordinate `Y` and
stores `Yd = Y + a*ZZZ`, adding affine `(xq,yq)` obtains the ordinary slope
numerator from `(yq+a)*ZZZ - Yd`. The addition can omit the final
`yq*ZZZnew` multiplication and store its core ordinate instead, making `yq`
the next anchor. This induction applies to every intermediate table point.
Only the final addition resolves the ordinary ordinate required by recovery.

The two-point deferred prefix costs 3M+2S, twelve intermediate additions cost
7M+2S each, and the resolving final addition costs 8M+2S. The complete
15-point fixed-base sum therefore falls from 108M+28S before the seed work and
107M+28S in the first deferred-seed archive to **95M+28S**. In native code the
uniform `c != 14` path skips 143 instructions, including all 73 wide multiply
instructions of one field multiplication, exactly twelve times per candidate.
The fast prepare kernel uses 124 registers, no stack or spills, and 5,976 SASS
slots; fallback prepare uses 124 registers, a 192-byte suffix stack, no spills,
and 6,320 slots. Finish, builder, and hierarchy kernels are unchanged.

`audit_deferred_chain.py` independently compared the old exact chain and the
deferred recurrence on 20,000 arbitrary-field accumulations, 1,000 curve
accumulations, and 1,000 complete mixed-window accumulations. It also checks
the production source form and the invariant after every intermediate point.
All inherited field, root, vector-state, finish, and SHA-tail audits pass.
