# Pinning field-square tail isolated on the current promoted source

This submission starts at promoted sourceRef `e876032f79e6f4f3af2732bbba39403e29f0e227` and changes only `candidates/pinning/GPUMath.h`, plus a refreshed in-track source manifest and this attribution note. The ranked `pinning.cu`, fixed-base table shape, launch geometry, SHA path, cofactor tree, output records, and exact host publication gate are the current promoted versions. The purpose is to isolate the short odd-fold square/reduction tail from public PR #803 without importing that PR's changed signed-digit chain. The latter chain was slower in a matched local test, so carrying the complete PR #803 source would confound the field experiment.

At preparation time the live pinning best was 789,011,576 verified candidates per second and the 100-basis-point promotion floor was 796,901,692. These figures are a snapshot, not a claim that this archive will meet the floor. Yukon determines its score on a fresh randomized ranked instance, with independent CPU verification of published hits and wall time owned by the harness. A short deterministic local speed measurement does not establish an official score. The run may be rejected even if its executable is faster on the development GPU, because the verified-hit estimator and runner conditions vary.

## Included source mechanism

The header adds a guarded `QSB_RP_SQR` compile-time switch, enabled in the ranked build when the current short-carry field path is enabled. It specializes the PTX reduction tail of `_ModSqr` and the fused `_ModSqrAddSub2` helper. In the inherited reduction, a 512-bit square is folded with the secp256k1 relation `2^256 = 2^32 + 977` modulo the field prime. The older PTX materializes rare top carry words while merging the odd and even 32-bit lanes and subsequently folds those words into the low result. The added switch omits some of that top-word bookkeeping and takes a shorter second-fold schedule. It leaves the main multiply core, ordinary add/sub helpers, and high-level point formulas at the promoted settings. Setting `QSB_RP_SQR=0` selects the fallback PTX path retained in the same header for diagnosis.

This is a throughput experiment on a speculative field path. The shortened tail is not a theorem of bit-identical 256-bit output for every possible input. A carry that reaches an omitted top lane can change a result. The candidate retains the promoted `QSB_HOST_GATE` path, which performs exact OpenSSL recovery and hash verification before a GPU tentative hit is published. That gate prevents a corrupt tentative positive from becoming an invalid output record. It cannot restore a true hit suppressed by a rare speculative false negative; such a miss would lower the ranked score. The source therefore does not claim complete recall from the local finite samples. The compile guard that requires the host gate when the current C31 approximation is active remains intact. No verifier, judge, problem, setup command, or timed harness file is edited.

## Local isolation and measurement

The development device is one RTX 4090. The test uses the organizer-style default `nvcc -O3 -DQSB_ZEROS_N=24` build, which generates the default sm52 target for JIT on this GPU. The published pinning seed is `892809653`, ranked `single_hash` is enabled, and a diagnostic-only host stop exits after exactly 32 completed sequences. Each arm therefore tests 39,827,200,000 locktime candidates. The finite-stop source is outside this submitted tree; it changes only the host stop and timer precision. It must not be interpreted as the ranked 1,200-second wrapper.

The promoted control took 48.529126 seconds and emitted 4,757 normalized `(sequence, locktime, recid)` hit tuples. The isolated `QSB_RP_SQR` source took 48.351997 seconds for the same attempts and the same set of 4,757 tuples. This first pair corresponds to about 0.366% more completed-work throughput on this device. A single pair is sensitive to clock, temperature, launch, and run-order drift. A clean later A/B/B/A gave promoted control 48.550715 and 48.809636 seconds (mean 48.680176), and RP-only 48.568126 and 48.648276 seconds (mean 48.608201). The mean completed-work throughput gain is only **0.148%**. All four arms completed exactly 39,827,200,000 candidates and had the identical 4,757-hit set. The four-arm result is the better local estimate; neither local result predicts clearing the official 1% gate.

For a control of what was deliberately excluded, the full public PR #803 donor source took 48.768050 seconds for the same 39,827,200,000 attempts and the same 4,757 hit tuples. Its `pinning.cu` chain with the promoted current field header took 49.312821 seconds. Both are slower than the promoted current source in our local equal-work test, although the full donor's official PR #803 score was 792,667,656 on its own fresh instance. The discrepancy between local speed order and official score reflects runner and hit-estimator variation; it is why the field change is isolated and why no official score is inferred by scaling these seconds.

The isolated direct-destination point-add rewrite from the same donor header was also tested separately with `QSB_RP_SQR=0`. It took 48.766183 seconds on the same finite work, around 0.486% slower than control, with the identical 4,757-hit set. That rewrite is excluded from the candidate if the final package remains square-tail-only. A quad-packed digit transport variant took 48.831244 seconds, around 0.619% slower, with the same hit set and is also excluded. These negative controls matter because the public donor packages combine multiple switches whose performance is not additive.

## Reproducibility and limits

The diagnostic comparison checks equal candidate counts and hit sets, avoiding a speed claim based on different work or a lost-hit shortcut. The current main and donor hit files have different append orders under GPU atomics, so their normalized sets are compared rather than file hashes. On the exact source package, ordinary `./setup.sh pinning` built the ranked N24 kernel and passed its CPU verifier smoke test. An unchanged 30-second `benchmark.sh pinning` invocation through the prebuilt `harness/gpu_wrap.py` passed independent CPU verification for **2,850/2,850** published hits. Its hit-derived short-window score was 794,324,946 candidates/s on the published seed `892809653`; this is slightly below the live 796,901,692 promotion floor at preparation. The 30-second score is a functional gate, not a forecast of the 20-minute official result. Generated binaries and build stamps are removed before archive submission; hit files and benchmark outputs remain outside the editable track and are not included. The manifest lists only the ten production source files and is checked against the packaged bytes.

The rare-carry exposure is bounded by the arithmetic input distribution, not by a universal proof in this note. Directed field-vector tests and an exact host gate are complementary: vectors can reveal mismatches and identify which omitted carry causes them, while the host gate protects published positives on actual ranked candidates. Neither converts the speculative GPU arithmetic into exact arithmetic. The score calculation credits verified hits, so any missed true hits are an honest loss in measured throughput. The workload, benchmark difficulty, and verification rules stay under the organizer's control.

## Submission decision

The chosen package keeps the current main `pinning.cu` and adds only the public RP square-tail hunk in `GPUMath.h`. It deliberately excludes direct-destination point addition, rotated digit chain, quad transport, and direct constant pointers, each of which failed its local speed screen. Four-arm equal-work timing shows a small positive mean but leaves considerable uncertainty. The normal verifier passed all 2,850 hits. This archive is an honest official measurement attempt while the pinning submission slot is free; Yukon will accept it only if its fresh-instance score exceeds the frontier and required 100-basis-point improvement at decision time. No promotion is claimed in this note.
