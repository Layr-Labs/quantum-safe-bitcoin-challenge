Base: the workspace's own HEAD `ff27a2b` = promoted `fb6f5a8` (cefika, 728,337,167),
byte for byte apart from the changes named below. All numbers are dev-rig (RTX 3090,

## Changes (all in candidates/subset/tests/gpu_epochs/tree.cu defaults, #ifndef-guarded)

1. QSB_TAIL_STAGGER 0 -> 1 (PARK128 1 -> 0, forced — STS.128 parking is incompatible
   with the split tail). The two paired tails run in a warp-group-dependent order
   (FFGG for warps 4..7, FGFG for warps 0..3), so the two warps a block has on one
   sub-partition put different pipes under load simultaneously (finish is
   fma-heavy 0.37/warp-cycle, gate ALU-heavy 0.46; the base's uniform FGFG has both
   gate warps saturating ALU while finish warps idle it).
   - N=24 scored path, 4 interleaved pairs: 371.57 vs 366.78 M/s = +1.31% (4/4 pairs
     positive: +1.12/+1.14/+1.53/+1.44 pairwise).
   - N=4 local census (earlier): +0.51% — the N=4 protocol under-reads because its
     ~5700 hits/s CPU co-grind flood perturbs the kernel; N=24 (~19 hits/s) is the
     honest difficulty.
2. [stack arms to be filled from the census results: ROOT_LUT_SMEM / ROOT_WARP 2 /
   R_CBANK_TAILS / TAIL_STAGGER=4]

## Exactness

Each knob above is documented bit-identical in tree.cu (same values, same order,
same hit records): stagger only reorders two pure tail calls per warp group;
ROOT_LUT_SMEM moves the root's divstep table to shared memory (same words at the
same indices); ROOT_WARP changes only which lanes compute the tree top (same
products/inverses); R_CBANK_TAILS moves a constant read into the callee.
The dev-only QSB_LOCAL_SM86 geometry gates leave the ranked build at promoted
values (verified: the #if blocks take the #else branch when the macro is undefined).
