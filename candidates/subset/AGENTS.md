# Subset work

When subset is selected, keep source changes in `candidates/subset/`. Prioritize large architectural gains.
Read `RESEARCH.md` and the latest public frontier before selecting another
experiment. Attribute substantial unpromoted source with Yukon coauthors.

Run `python3 candidates/subset/check_candidate.py` after changes to the source
it extracts. Treat its result as a CPU reference check, never as CUDA execution
or a GPU benchmark. Keep the included GPU arithmetic audit available. Record
returned validation failures and improve the checks that missed them.
For deferred-Y helper changes also run `check_deferred_source.py` and
`audit_integrated.py`. The former executes extracted helper bodies with OpenSSL
field operations; the latter is an independent model. Neither is a GPU test.
Those legacy source assertions assume the earlier regular16 layout. For an
isolated different geometry, use `research/wide_windows/check_wide.py` with
explicit expected widths, point order and prefetch range instead; it executes
the selected chain against an independent OpenSSL curve oracle. Changes to
the cold-first final helper also require its `check_exceptions.py`, which tests
the actual helper against the independent affine law, constructed scalar
witnesses and prefix bounds. Record the source fingerprint and distinguish
legacy-check incompatibility from candidate failure. Do not claim full-domain
correctness merely because random checks pass; reordering incomplete additions
requires an exceptional-domain argument or a complete fallback.

intended source and relevant checks in an isolated checkout when needed, while

Record CPU results with `check_candidate.py --report <temporary-report.json>`
and match its source fingerprint before relying on an older test result.
After changing table geometry, execute the actual host startup/policy code with
that geometry as well as device/chain checks. The thirteen-window prototype
compiled and passed curve tests but still exited because L2 policy checked the
old window12 boundary instead of9. `preflight.py --package-check` now requires
`startup-policy-validation.json` (or `--startup-policy-report`) matching the full
current closure, with the actual policy capacity/error matrix and after-build
call check. Use the candidate-local policy checker with independently expected
widths; retain the old wrong-boundary failure as a regression. Compilation and
unchanged host-header hashes alone do not qualify a new geometry's startup.
On a CUDA host, `preflight.py --cuda` compiles both sources in a fresh temporary
tree. The trusted wrapper's build cache checks only `subset.cu`'s timestamp;
after a header edit, invalidate the generated `subset` binary and `.subset.build`
stamp before `yukon setup --track subset` and a local benchmark. A clean temporary
compile alone does not refresh that wrapper cache or prove GPU correctness.

For native optimization screens, bind every resource report to its source
fingerprint and distinguish stack bytes, compiler spill totals, and actual

as the active compact loop. Before rejecting or promoting a substantial
experiment based on spilling, inspect the relevant SASS/CFG where feasible;
a reported spill total alone does not locate repeated hot-path traffic. Record
unknown placement explicitly and never convert static code counts to speed.
