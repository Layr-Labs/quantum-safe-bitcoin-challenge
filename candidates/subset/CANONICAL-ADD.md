# Canonical sparse-prime addition

Parent: completequad `8ac52bd0e63908c88fd7acb45af6661263572d88`, with complete final point addition and bounded quad32 inverse. PR232 / odinfree (`e8d949fa595fe366efdcdeb14acf59f7de42ce2b`) motivated examining the canonical-add cost, but its disclosed noncanonical serialization exposure and dropped final carry are not imported. This implementation uses our existing audited cold field correction, retains the carry, and returns a canonical result for all unsigned 256-bit input pairs.

Write B=2^256, C=2^32+977, p=B-C. For 0<=a,b<B, S=a+b<2B. The four-limb sum plus its high bit gives R=(S mod B)+C*floor(S/B), with 0<=R<B+C and R congruent to S modulo p. Retain the carry from that fold. If R>=B, its low part is less than C and adding C gives R-p<2C<p. If p<=R<B, adding C modulo B gives R-p. Otherwise leave R unchanged. These cases prove a canonical answer with at most one cold correction.

The hot boundary prefilter checks whether the upper 32 bits of the low result are zero or all ones. A retained carry implies low<C, and a canonical subtraction requires low>=p, so this prefilter has no false negatives. The reused cold helper checks the exact carry/range condition; false positives leave the original words unchanged. Multiplication and squaring use the same helper body as before. The helper is moved earlier in the header only so addition can call it.

The literal PTX semantic model passes 62,798 operand pairs, including targeted sums around p, B, 2p, B+p and 2B-C. It exercises 1,080 retained fold carries and 1,568 canonical subtractions. The device audit requires exact canonical equality for separate output and both input-alias modes. The complete-point audit is also required because canonical coordinates reach point comparisons, inverse input and SHA serialization. No rare error is accepted in exchange for speed.

The existing host projection branch retains the parent's canonical-input implementation. GPU arithmetic, the subject of this optimization, has the wider unsigned 256-bit input proof above. No source from the PR232 implementation is copied. Parent field, point, inverse and SHA attributions and COPYING remain unchanged. Performance is unmeasured until a same-toolchain GPU comparison is recorded.
