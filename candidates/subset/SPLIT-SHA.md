# Subset: separate paired SHA production from the EC consumer

Base: official main `7c3609b87b9d8e094a16be148fe846dfd5ac7807`, whose current subset implementation was promoted at `9ac2515450446dbadbe061e98ebfc317c36d4999`. Model: GPT-6. Harness: Codex.

The new producer calls the existing `qsb_pair_epoch_z_value` unchanged and writes its two SHA256d scalars into eight coalesced uint64 planes. `kernel_digest` reads those same scalars and retains the existing EC arithmetic, paired inversion, speculative filter, candidate identity and exact replay. Separating the SHA live ranges lets that producer run with fewer registers and keeps the digest instruction stream smaller. The first-state producer, group enumeration, window choices, hit handling, and all frozen benchmark files are unchanged.

The producer and consumer use the same physical grid, `QSB_PAIR_MUL`, `QSB_SE_WINDOWS`, lane and epoch identities. Missing A aliases epoch zero; missing B aliases A, exactly as the original consumer. Inactive lanes still participate in the inverse-tree barriers and cannot publish hits. A 4 GiB buffer is allocated once at the existing default 134,217,728-candidate launch size (32 bytes per candidate); it is overwritten on every launch on the same stream. The change adds 32 bytes written plus 32 bytes read per candidate. Allocation failure exits with an error. `QSB_SPLIT_SHA=0` restores the inherited monolithic computation.

Only the selected `candidates/subset` surface changes. Setup, nvcc command, CLI/argv, output record format, generator, scoring and CPU verifier remain unchanged. This is an exact scheduling and representation change, not a new speculative arithmetic approximation or a change in candidate selection.

Local validation uses fresh synthetic problems, a Windows RTX4060 Laptop and NVRTC12.4. A diagnostic adapter supplies the same exact unsigned-128 carry semantics in both arms because this Windows NVRTC does not support device int128; the submitted source retains the original int128 code. The final production `tree.cu` is read directly for the source-accurate diagnostic; the host scheduler is reproduced separately in Python. These timings are **not official nvcc or RTX4090 scores**.

At the full existing launch capacity of 134,217,728 candidates, the final production-source diagnostic gave **+9.97% throughput by mean time**: 1258.579 ms baseline versus 1144.451 ms candidate. All four paired ABBA groups were positive: +8.33%, +6.67%, +13.31%, +11.42%. The measurement includes the complete grouped producer, first-state producer, new scalar writes/reads, EC consumer, exact replay, and launch costs. It uses an eight-second warmup and two complete launches per timed observation. The 4 GiB scalar buffer is exercised at its full allocation and stride. Seed 515389412 at diagnostic N21 returned identical 124 hits; the unchanged official CPU verifier accepted 124/124 for both arms with the normal sufficiency gate.

A separate final-source run at 4,194,304 candidates on seed 1501409202 returned identical 141 hits, with official CPU verification 141/141 for both arms; mean times were 41.7686 ms baseline and 34.9758 ms candidate. The full-capacity +9.97% result governs the performance claim rather than the smaller-batch approximately 18% gain. Both final-source runs independently checked 64 scalar values against Python/hashlib SHA256d of official reconstructed preimages.

Partial-batch tests at 1, 2, 3, 5 and 7 epochs checked every produced scalar, including inactive and absent-B aliases: 3,584 exact SHA256d comparisons. Baseline and candidate hit sets matched for all five cases. Their combined 286 hits on a separate synthetic problem passed the unchanged official verifier with the normal sufficiency gate. These are runtime synthetic correctness inputs, not compiled-in problem values.

NVRTC emits a 128-register, 24-byte-local-memory baseline consumer and a 128-register, zero-local-memory new consumer; the new SHA producer uses 56 registers with zero local memory. The promoted author's CUDA12.8 nvcc record reports zero spills in the old consumer, so part of the local gain may not transfer. In the warmed default-capacity stage diagnostic, the old consumer took 1299.31 ms; the split SHA producer took 189.92 ms and new consumer 983.93 ms, while other stages totaled about 9.6 ms. Stage timing is supplementary; the full-pipeline paired observations determine the local claim. Official remote validation is authoritative; no official improvement is claimed in advance.
