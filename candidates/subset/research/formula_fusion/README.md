The implemented isolated candidate is `candidate/`, fingerprint
`7afe2d8642468c1245febc0aa9d159c76e6724e44035497a1d6623b75256c37e`.
It derives only from frozen fused-small48 source
`b832d7ba4ec2b2554aa5279e46858a5163e83e3ad7e714e9b108551165c95f7b`.
Only `tests/gpu_epochs/tree.cu` changes. Production, prepared submission stages,

The concrete implemented result is three fewer field squares, with the same

## Implemented recovery rewrite

Write the finite source point as

```
P = (X/A, Y/B),  A=ZZ, B=ZZZ, B^2=A^3,
R = (r,s),       r^3+7=s^2,
d = r*A-X,      delta = r-xP.
```

For nonzero `A,B,d`, invert `W=B*d` through the unchanged block inverse.
Then compute

```
h = A/W
k = B*h = 1/delta
beta  = Y*h = yP*k
alpha = s*k
c = 3*r^2 mod p                  // once per runtime problem
center = 2*alpha^2 - c*k + r
cross  = 2*alpha*beta
x1 = center-cross
x2 = center+cross
lambda1 = alpha-beta
m2 = alpha+beta
y1 = lambda1*(r-x1)-s
y2 = s-m2*(r-x2)
```

The two ordinates need only their canonical parity, exactly as before. The
existing negative-parity convention for the second recovery flag is retained.
`A`, `B` and `Y` storage is reused for `alpha`, `c*k` and `beta`; no new point
state crosses the inverse. `A` replaces the old carried `C=A*d^2`.

**Proof.** Both input points satisfy the same curve equation. With
`xP=r-delta` and `k=1/delta`,

```
beta^2-alpha^2
 = ((r-delta)^3-r^3)*k^2
 = -3*r^2*k + 3*r - delta.
```

Substitute this into `(alpha-/+beta)^2-(xP+r)`. The result is precisely
`2*alpha^2 - 3*r^2*k + r -/+ 2*alpha*beta`. The slopes and affine Y formulas
are unchanged, so this proves both X coordinates and both parities.

This identity needs the actual curve equation; it is not valid on arbitrary
off-curve coordinate tuples. The audited guarded chain produces valid XYZZ
points, and `R` comes from the runtime problem. For valid XYZZ states, the new
`B*d` denominator is zero exactly when the old `A^2*d` denominator is zero.
The existing identity-padding and singular-lane skip contract is unchanged.
It does not add a full recovery fallback for `P=+/-R` or infinity.

| Ordinary per-candidate region | Existing | Rewrite |
| --- | --- | --- |
| Prepare, including old C | 3M + 2S | 2M |
| Finish | 7M + 2S | 8M + 1S |
| Total recovery | 10M + 4S | 10M + 1S |
| Modular adds/subtracts in recovery | 11 | 13 |
| Whole 14-point chain plus recovery | 98M + 30S | 98M + 27S |

These counts exclude the unchanged inverse collective, SHA and point-chain
additions. The new runtime constant requires one checked OpenSSL square,
integer multiplication by three, modular reduction and 32-byte constant upload
per problem, inside startup. It is computed from the supplied `u2r_x`, without
precomputed problem data. The additional CUDA constant occupies 32 bytes.
There is no throughput prediction from these counts.

`prepare.py` anchors the complete source fingerprint and refuses to overwrite
an existing candidate. `prepared-source.json` records changed files and costs.

## Larger open region: carry deferred Y as two factors

This is analysis only, not part of the candidate above.

Every deferred addition stores

```
Ycore = R_old * (V_old-X_new) mod p.
```

The only use of `Ycore` in the next addition is

```
R_new = (y_next+y_anchor)*B - Ycore mod p.
```

Instead retain the two canonical factors
`L=R_old`, `T=V_old-X_new`, and evaluate one compound primitive

```
R_new = muldiff((y_next+y_anchor) mod p, B, L, T)
        = ((y_next+y_anchor)*B - L*T) mod p.
```

There are twelve such boundaries in the frozen fourteen-point chain: the seed
and eleven deferred intermediate additions each feed a following addition.
Each boundary currently performs two separate product reductions; the compound
operation performs the same two 256-by-256 raw products and only one reduction
of their difference. Thus the exact opportunity is **twelve fewer separate
512-to-field reductions**, not twelve fewer multiplications. With 8x32-bit
schoolbook products, each fused pair still contains 128 operand partial
products before reduction arithmetic.

The final exact ordinate provides a thirteenth independent two-product region:
`Y = R*(V-X)-y_last*B`. It can use the same primitive without carrying factors
into recovery. No other consumer needs either unreduced intermediate. Combined
native savings are not assumed additive.

**Range and carry contract.** For canonical inputs `a,b,c,d` in `[0,p)`,

```
D = a*b-c*d
-(p-1)^2 <= D <= (p-1)^2.
```

A signed 512-bit accumulator is insufficient. An unsigned 512-bit subtraction
result `U` plus its borrow bit is sufficient. Since `p=2^256-C`,
`C=2^32+977`,

```
D mod p = (U - borrow*C^2) mod p,
2^512 mod p = C^2.
```

Discarding the borrow fails the explicit negative controls. An alternative
nonnegative representation `D+p^2` lies strictly between zero and `2*p^2`,
requiring 513 bits. These are mathematical width bounds, not a requirement to
materialize both complete products simultaneously; a streaming column/carry
implementation remains possible but unimplemented. Existing primitive carry
witnesses must be retained when implementing it.

The factor representation replaces one 256-bit ordinate by two 256-bit
factors: **32 additional bytes, or eight logical 32-bit words**, across each
table-load/add boundary. The frozen fused kernel already uses 128 registers
with no spills at its launch bound. This extra live state makes a native
register/spill screen necessary before treating the reduction savings as
useful. No reduced-state layout, efficient PTX `muldiff`, or GPU result exists.
The existing final-add `P=0` equal/opposite guard must remain; the fused
numerator must be canonical before its zero test.

## Bounded negative findings and prior-work distinction

Merely retaining last-window Y in deferred form does not remove a multiply from
the current direct XYZZ recovery. The existing terminal resolution `y_last*B`,
recovery `yR*B`, and two slope products cost four multiplications. Directly
forming `(yR+/-y_last)*B-/+Ycore` still needs two biased-B products and two
slope products: four multiplications. In the cubic rewrite, replacing
`Y*h` by `Ycore*h-y_last*k` similarly spends the multiply previously saved in
the terminal resolve. This is a bounded comparison, not an optimality proof.

Public subset submission `8339d955` previously carried a deferred anchor through
homogeneous conversion and affine Y reconstruction, saving one multiply on that
different old architecture; it scored 441,645,545 and was rejected. The current
rewrite instead changes the recovery denominator and uses the cubic curve
equation to eliminate three squares. The local `comb16/check_transition.py`
co-Z screen concerns a 2P+Q transition at 15M+4S versus 13M+6S with incoming Y
resolution; it is a different operation and supplies no lower bound here.
`muse/memory.md` leaves unreduced formula regions open and explicitly requires
width, carry and register accounting; the twelve-boundary `muldiff` contract
above makes one such region concrete.

Remaining open work is precise: GPU correctness/performance qualification of the
implemented cubic recovery; an actual carry-correct `muldiff` primitive; and a complete-kernel
factor-state register budget. No broad formula-optimality or performance claim
is made, and the pending external submission remains preserved.

square primitives. Neither checker executes CUDA collectives, native PTX field
