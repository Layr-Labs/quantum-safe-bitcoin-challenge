# Subset: the record `fb6f5a8f` with jacklightChen's co-grinder data-flow cuts (`b1c5e58e`), kshitij-hash's `QSB_CPU_ILP2` bit 1, and two of the record's own exact device switches, `QSB_Q_MIX` 2 and `QSB_R_CBANK` 1 (a new native image)

Effort: max. Prepared with Claude Opus 5.5 in Claude Code on an RTX 4090 + i7-13700K host (CUDA 12.8.93).

## Starting point

The promoted subset record is `fb6f5a8f` (cefika), 728.34 M/s: GPU part 662.35 M/s and co-grinder part 65.99 M/s from its public hit list (window-triple classification: the GPU walks the 128 triples of the late window, the co-grinder the other 158). The promotion bar is 735.62. Our previous ticket `f01f19c7` (ranked 716.71 M/s, GPU 647.46 + CPU 69.25 M/s) was our `kjc_i3` package (the same host side with the record's Q layout `QSB_Q_MIX` 4, `QSB_R_CBANK` 0 and image `e0c0897f`).

## What this package is

Every file is cefika's `fb6f5a8f` at its benchmarked commit `ff27a2b6` (kshitij-hash's `e6715658` device side with cefika's contiguous-epoch co-grinder walk) byte for byte, except four:

- **`subset.cu`, lines 1-2:**
  - line 1 is our inert tag (a `#define` nothing references);
  - line 2 is `#define QSB_R_CBANK 1`. That is the record's own kill switch, documented in `tests/gpu_epochs/pair_shared.cuh` and 0 in the record. With it, the paired front and tail read the recovery point R from the constant bank inside the `__noinline__` callee. In the record they receive R as eight 64-bit ABI register arguments, which the digest kernel holds live across both fronts, the tree inverse and both tails. The `__constant__` words and the field operations are the same, so the results are bit-identical.
- **`CpuGrindSubset.h`:** jacklightChen's version from public submission `b1c5e58e`, with `QSB_CPU_ILP2` 3. These are the same host-only changes as our previous `kjc_i3` tickets.
  - jacklightChen's seven exact co-grinder data-flow cuts, all on: `QSB_CPU_INV_LAST`, `QSB_CPU_KH16_PAD_ONCE`, `QSB_CPU_KH16_REGMASK`, `QSB_CPU_PARITY_CMP`, `QSB_CPU_KH16_WORDS52`, `QSB_CPU_INV_LANE0` and `QSB_CPU_INV_FIRST`. jacklightChen's own audits are in that submission's note.
  - kshitij-hash's `QSB_CPU_ILP2` bit 1: `ec8_window`'s forward pass steps two groups op by op. It does the same operations on the same operands in another order. On the 8-lane IFMA path under Intel SDE (Sapphire Rapids, one worker, 196,608 fixed candidates at N = 12) the hit set is the same, 93 hits, byte for byte as with `QSB_CPU_ILP2` 1.
- **`tests/gpu_epochs/tree.cu`, one line:** the default of `QSB_Q_MIX` goes from 4 to 2.
  - `QSB_Q_MIX` is the record's own switch for the layout of the Q table the device walk reads. Every layout is the record's code and reads the same values.
  - i34-9 and terrapinelf have drawn `QSB_Q_MIX` 2 on the ranked host (`c524f296`; `3a8ff1e4` in a larger stack).
- **`qsb_carrier_sm89.h`:** the native sm_89 image, regenerated with CUDA 12.8.93.
  - Its cubin sha256 is `d8566853a25323de…`, 473,248 B.
  - `kernel_digest` uses 128 registers, 1 barrier and 49,152 B of shared memory, with no stack frame and no spills.
  - The image was built twice, once with both switches given as compiler flags and once from the edited source. Both builds produced this cubin byte for byte.
  - The host binary's knob string matches it, so the carrier loads natively.

## Why this draw

The co-grinder side is the replicated gain of our `kjc` / `kjc_i3` tickets: jacklightChen's cuts read 67.6-69.7 M/s luck-free on the ranked host (mean 68.8 over six of our draws on 10-01/10-02), against 66.5-68.4 M/s (mean 67.4) for six draws of the record's bytes in the same hours.

The two device switches are the only ones that survived two local sweeps and a 10-round confirmation each. The method is an interleaved ABBA run on the 4090 (the same problem and binary arguments, 60 s per run, every control rebuilt by the same toolkit). Each step is measured against the step before it:

| step vs its control | sweep (4 rounds) | 10-round confirmation |
|---|---:|---:|
| `QSB_Q_MIX` 2 vs `kjc_i3` | +0.40% | +0.24% (10 of 10 rounds positive; paired SE 0.03%, t 8.7) |
| `QSB_R_CBANK` 1 on top of `QSB_Q_MIX` 2 | +0.22% | +0.22% (10 of 10 rounds positive; paired SE 0.04%, t 5.2) |
| second session: `kjc_i3` -> `QSB_Q_MIX` 2 / `QSB_Q_MIX` 2 -> + `QSB_R_CBANK` 1 | | +0.12% (8/10, t 2.6) / +0.15% (9/10, t 2.8) |
| direct: this package vs `kjc_i3` | | +0.08% (10 rounds, SE 0.05%) |

These switches were rejected:

- `QSB_YP_FOLD_DROP` 1 looked like +0.24% in the sweep but read +0.02% in its confirmation; it is also not exact.
- Fifteen other device flips read null or negative.
- Nine flips do not build on this base.

## Reproducing

- Start from the record's benchmarked commit `ff27a2b6`. A `diff` of `candidates/subset` against this package lists exactly the four files above:
  - lines 1-2 of `subset.cu`;
  - `CpuGrindSubset.h`;
  - the `QSB_Q_MIX` default in `tests/gpu_epochs/tree.cu`;
  - `qsb_carrier_sm89.h`.
- `NVCC=<CUDA 12.8.93 nvcc> ./build_carrier.sh 24` regenerates `qsb_carrier_sm89.h` with cubin sha256 `d8566853…` byte for byte.
- The harness line (`benchmark.sh subset` with `QSB_GRINDER=cmd:… gpu_wrap.py`) builds the host binary against the committed image. The grinder's log line `Native sm_89 carrier: on (… d8566853 …)` confirms that the native image runs, not the JIT fallback.

## Caveats

- **The size of the device gain is uncertain even locally.** Each switch read positive against its own control in two separate sessions (table above). A direct A/B of this package against `kjc_i3` read only +0.08%. Session-to-session effects of about 0.2% exceed the within-session error. Our best estimate is about +0.2% of the GPU rate (range +0.08% to +0.46%). Both switches are exact, so the package is never worse than `kjc_i3`. On other bases `QSB_Q_MIX` 2 read flat or negative before: our 09-28 Y_PAIR-base tests, and i34-9's ranked draws before 10-01.
- **One draw is noisy.** The GPU part of a single ranked draw varies by several M/s between draws of the same bytes. The runner's level drifts between windows, so a draw can land above or below the record's own draw.
