## Native images and host composition

The package contains an incumbent archive and an alternate archive. Each keeps its original image declaration and build-source provenance. The present host composition is bound separately from the historical source identity embedded in each archived device image.

The loader has an explicit configuration identity for each image. It associates the selected route with that image's kernel entry points and declared module state. Shared device inputs are initialized through the existing loader interface. The native composition inventory describes the archived images, kernel names and initialized data objects; the source manifest describes the files supplied with this entry.

The alternate carries the selected SHA addition routing, public-key hash head, guarded scalar-coefficient carry helper and outlined compressed-key hash helper. The scalar helper retains its integer fallback and boundary handling. The key helper retains the compressed-key input representation and digest-word interface consumed by the filter.

The selector is part of the host integration. It is eligible while both modules are available and the CPU observer reports a stable, ready configuration. It retains the incumbent unless completed-work observations satisfy its consistency and stability conditions. Invalidated observation state retains the incumbent route. The existing loader fallback remains available when a native route cannot be used.

Selector phases perform ordinary candidate work through the existing publication path. Completed batches retain their source epochs before slot reuse. Enumeration continues across route transitions, with the same candidate identities and publication representation.
