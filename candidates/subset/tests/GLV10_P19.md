# Shared five-bank GLV experiment

This experiment starts from the unpromoted GLV11 donor, local snapshot
`a8c9a7d` of public submission `7ee5c52a`. It retains the donor's notices,
exact GLV split, point helpers, host verification, and native carrier.
The shared implementation defaults `QSB_GLV10_P19` to zero. This isolated
worktree's `subset.cu` wrapper opts in with value one, so normal executable
and carrier builds agree. Compile both with `-DQSB_GLV10_P19=0` to select
the original donor geometry and cache policy. Rebuild the carrier after
source or build-option changes.

Both signed GLV components use the same five banks:

| Bank | Shift | Field width | Records | Record offset |
| --- | --- | --- | --- | --- |
| 0 | 0 | 19 unsigned | 524288 | 0 |
| 1 | 19 | 27 signed | 67108864 | 524288 |
| 2 | 46 | 27 signed | 67108864 | 67633152 |
| 3 | 73 | 27 signed | 67108864 | 134742016 |
| 4 | 100 | bounded top | 85279885 | 201850880 |

Bank zero stores `(K+i)*A`, where `K=(170559770<<99)-(1<<18)`.
The middle banks store `(2*i+1)*2^(shift-1)*A`; their digit is
`2*field+1-2^27`. The top bank has digit `2*field-170559769`.
The biases telescope to each component's exact magnitude. All fields total
128 bits, preserving the existing packed scalar walker's handoff between Q
and P. The endomorphism applies after Q's fifth term.

The table has 287130765 records and uses 18376368960 bytes (17.114 GiB).
Only the first 32 MiB is marked hot. The experiment requests a matching
persisting L2 set-aside, subject to device limits. Its second seed is cold
and receives the same native 64-byte fetch hint as later cold records.

The source-level point arithmetic falls from `68M+20S` to `61M+18S`, including
the endomorphism. Total payload falls from 704 to 640 bytes per candidate,
but cold payload rises from 384 to 512 bytes. This can lose on memory latency
or bandwidth. It is not a promised speedup.

Run the bounded CPU audit from the repository root:

```sh
python3 candidates/subset/tests/glv10_p19_audit.py
```

It compiles actual portable helpers, descriptors, geometry, startup checks,
and the host table-coefficient expressions. Independent integer arithmetic
checks recoding, GLV reconstruction, signs, group-order reduction, and every
bit boundary. Sparse OpenSSL point sums check ladder decomposition and the
whole signed chain under varying runtime bases and isomorphic scalings.
Python's `cryptography` package and a C++17 compiler are required.

The completed CPU audit passed 22306 exact recodings, 76 sparse ladder
records, and 192 sparse OpenSSL chains. The donor and P19 compiled startup
checks both passed. An independent reviewer also checked 20812 signed
geometry cases against separately derived integer coefficients.

This audit does not execute CUDA field arithmetic or the large GPU table
builder. The donor's speculative filter behavior at exceptional points is
unchanged; the CPU point oracle handles those cases exactly. Native sm_89
compilation, device table checks, regenerated carrier verification, and paired
whole-search measurements remain required before any performance conclusion.
